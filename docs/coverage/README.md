# Stable module coverage

Dolibarr 24.0.3 ships **95 descriptors** in its core module directory. The module administration screen's stable filter admits **84**. Four declare experimental status, four development status and three deprecated status. These counts measure descriptors in the release. An individual installation can expose a different set because of its supplier configuration, organisation, enabled modules and instance settings. [Core descriptor directory](https://github.com/Dolibarr/dolibarr/tree/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules) · [Filter implementation](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/admin/modules.php#L995-L1009)

[Machine-readable module inventory](modules.json) provides the descriptor key, numeric module ID, functional area, upstream setup family, maturity, scope decision and pinned declaration for every module. Optional fields describe activation dependencies, conflicts and conditional visibility. The key is the case-sensitive class suffix (for example, `Facture`). Its activation constant is `MAIN_MODULE_` plus the uppercase suffix. Permission namespaces and public API resource names can differ. The inventory records scope eligibility. Chapter coverage is tracked separately in the [blueprint index](../../README.md).

## How to interpret the inventory

* **Eligibility.** A declaration of `dolibarr` follows the parent release. BlockedLog uses its own dotted version, **3.0.0**, which also passes the stable filter. The other eleven descriptors appear in the inventory solely to record their exclusion. Stability is checked again for individual features. A stable module can contain flags, unfinished screens and optional integrations with different support levels. Built-in shipment PDFs, for example, are a separate question from the maturity of the standalone DocumentGeneration descriptor. [BlockedLog declaration](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/modBlockedLog.class.php#L58-L64) · [Component version](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/blockedlog/versionmod.inc.php#L27-L33)
* **Visibility.** The setup screen discovers readable `mod*.class.php` files, requires the class to exist and skips repeated descriptor names. For inactive modules the feature level must be at least 2 for development, at least 1 for experimental, or negative for deprecated. Previously enabled modules pass this particular feature-level test. A truthy descriptor `hidden` property still removes the module from the list. A nonzero `MODULE_CRON_DISABLED`, for example, hides the scheduled-jobs descriptor. [Discovery and visibility](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/admin/modules.php#L562-L615) · [Scheduled-jobs descriptor](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/modCron.class.php#L64-L71)
* **Purchasing.** With the supplier split option off, the combined Fournisseur descriptor supplies the purchasing module and configuration exposes both order and invoice capabilities. With `MAIN_USE_NEW_SUPPLIERMOD` enabled, the combined descriptor class is absent and the separate SupplierOrder and SupplierInvoice descriptors become visible. Count the business flows once. Dependencies can branch on the option, including those for supplier quotations, batch tracking and bank transfers. Reception's descriptor still names Fournisseur directly, so exercising receipts with the split option warrants its own integration test. [Combined supplier descriptor](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/modFournisseur.class.php#L33-L40) · [Configuration mapping](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/class/conf.class.php#L866-L881) · [Receipt dependency](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/modReception.class.php#L66-L76)
* **Activation.** The setup action requires an administrator. Activation checks minimum runtime and application versions and any JavaScript requirement, skips an already enabled module by default, then initialises the requested module. It recursively activates the declared dependencies and disables declared conflicts. A country-specific dependency is skipped only when a country is present and fails the prefix comparison. This explains the inventory's `country_FR_or_unset` entry for TakePos. Errors from a dependent module are accumulated after the parent initialisation; reconcile the resulting state before retrying. [Setup action](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/admin/modules.php#L441-L469) · [Activation sequence](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/lib/admin.lib.php#L1203-L1335) · [TakePos dependencies](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/modTakePos.class.php#L100-L108)
* **Deactivation.** Setup requires confirmation. A successful ordinary removal follows the descriptor's explicit `requiredby` list, which is maintained separately from the forward dependencies in the inventory. Conflict removal suppresses that recursive cascade. The two accounting modes declare a mutual conflict. Users and groups is permanently enabled in the normal setup interface. For BlockedLog, the protected status depends jointly on prior activation, prior use and the configured country list. [Removal semantics](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/lib/admin.lib.php#L1310-L1418) · [Double-entry mode](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/modAccounting.class.php#L64-L68) · [Protected log](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/modBlockedLog.class.php#L98-L103)

## Reproducing the count

At the pinned upstream commit, enumerate the files immediately inside `htdocs/core/modules` matching `mod*.class.php`. Read each descriptor's version assignment, resolve component constants and apply the setup screen's maturity filter. Compare the full set of filenames with the keys in `modules.json`. Subdirectories contain other extension points, including document and reference-numbering models, which are examined with their owning workflows. External modules require separate release pins.

## Acceptance cases for configuration

| Setup | Operator action | Observable outcome |
| --- | --- | --- |
| Ordinary level, clean installation, supplier split off | Browse the stable catalogue | The combined supplier module can appear. The two split descriptors are hidden. Inactive experimental, development and deprecated descriptors are absent. |
| Products, orders and shipments disabled | Enable shipments with dependency resolution under valid setup conditions | Shipment activation requests customer orders, which request third parties. Products is outside this descriptor dependency chain. |
| Simplified accounting enabled, prerequisites available | Activate double-entry accounting | The activation path requests invoices, bank and tax, then disables the conflicting simplified mode. |
| Experimental module already enabled, feature level returned to zero | Browse all maturity levels, then filter explicitly to stable | The feature-level gate alone retains the enabled module. The explicit stable filter excludes it. |
| An existing module dependency fails after parent initialisation | Inspect the activation result and entity settings | The result reports dependency errors. Check the parent and each prerequisite independently before retrying. |
