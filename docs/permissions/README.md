# Permission declarations and effective access

The [permission index](declarations.csv) gives the numeric ID, declaring module, rights namespace, first- and second-level keys, English label, default grant, declaration condition and source line for **323 permission declarations**. The [descriptor index](descriptors.csv) covers all **84 eligible bundled module descriptors**, including 22 that declare no permission of their own. For example, the API descriptor contains a commented example for managing an API key. It adds zero permission definitions to this snapshot. API operations still enforce rights on the business resources they expose. [API descriptor](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/modApi.class.php#L135-L150) · [Stock movement API](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/product/stock/class/api_stockmovements.class.php#L217-L247)

## Reading the indexes

| Column | Meaning |
| --- | --- |
| `id`, `id_expression` | Numeric ID registered with the permission store and the original expression used to derive it. The 40 computed IDs include arithmetic, decimal concatenation and a zero-padded suffix. For instance, the reception validate permission has ID 941603. |
| `namespace`, `first_level`, `second_level` | Keys on the permission definition, preserving spelling and case. A blank second level is a two-part capability such as stock/create (`stock`, `creer`). The runtime can map an application's alternative name to these keys. |
| `english_label`, `descriptor_label` | The former uses an English `Permission<ID>` entry when present, then an English translation of the descriptor label, then the descriptor text. The latter retains the declared fallback label or translation key. A site's advanced-permission UI can display an alternate label. |
| `default_grant` | Declared default for new users, with omitted defaults interpreted as zero by registration. The sole enabled default in this snapshot is 40001, reading currencies and rates. Installed defaults and explicit assignments can differ. |
| `declaration_guard` | Enclosing conditions that affect whether the declaration executes, in addition to enabling the module. Blank means the declaration itself is unconditional. |
| `setup_hidden_when` in the descriptor index | Expression explicitly assigned to the descriptor's visibility property. A blank value means no explicit assignment appeared. The property controls module setup visibility; it does not grant a capability. |

## How a declaration becomes a decision

1. **Register a definition for an entity.** During module setup, registration checks the activation constant and materialises definitions. It uses a composite key of permission ID and entity. Administrative grants may also be initialised in this operation. [Registration](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/modules/DolibarrModules.class.php#L1990-L2139) · [Definition key](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/install/mysql/tables/llx_rights_def.key.sql)
2. **Build the user's effective rights.** The loader reads user assignments and assignments through group membership, with entity filters. It filters advanced right groups when advanced permissions are disabled and caches loaded rights. New-user defaults are a distinct assignment path. [Rights loading](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/user/class/user.class.php#L1385-L1635) · [Default assignments](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/user/class/user.class.php#L2217-L2259) · [User grants](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/install/mysql/tables/llx_user_rights.key.sql) · [Group grants](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/install/mysql/tables/llx_usergroup_rights.key.sql)
3. **Resolve a capability in context.** The runtime handles module names, aliases and the supplier split, checks module enablement, applies specific restrictions for external users and evaluates the permission levels. Field and record operations can impose further conditions. For example, the reception validation API requires creation permission and access to the target reception. With advanced permissions enabled the domain action also requires the advanced validation right. A default setting, an administrator flag or a category of permissions alone cannot establish that a particular user can act on a particular record. [Capability evaluation](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/user/class/user.class.php#L913-L1081) · [Reception API](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/reception/class/api_receptions.class.php#L583-L606) · [Domain validation guard](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/reception/class/reception.class.php#L645-L659)

### Acceptance cases

- A user with no direct grant but an applicable group assignment can load that capability for the active entity. An assignment in an unrelated entity does not satisfy the ordinary same-entity query.
- Receiving a purchase in normal and advanced permission modes can yield different outcomes with the same basic reception-create grant. Verify the route check, domain check and record scope separately.
- A newly activated module with zero declarations creates no new rights rows of its own. Its screens can still require another module's permission or administrative access.
- A user with a direct third-party export grant who is linked to an external third party is denied by the explicit external-user check for this operation.

## Reproducing this release

With a local Dolibarr checkout at the pinned commit, run the following from the documentation repository. The check compares both CSVs byte-for-byte and exits nonzero if either differs.

```sh
python3 tools/build_permissions.py ../dolibarr --check
```

The [extractor](../../tools/build_permissions.py) reads committed Git objects, preserving line numbers while excluding comments. It scans all eligible descriptors from the [release inventory](../coverage/modules.json), resolves positional and named field slots, tracks index counters, and resolves every active numeric ID expression in this pin. The generator rejects unfamiliar declaration shapes, ID expressions and overlapping IDs. The pinned eligible descriptors use field assignments; the inventory excludes commented examples and inactive module maturities. English lookup uses the pinned locale files in deterministic filename order. The result describes source declarations. Site-specific module activation, local overrides, extension-provided permissions, actual users and group memberships, runtime hooks, and individual document sharing require installation-specific evidence.
