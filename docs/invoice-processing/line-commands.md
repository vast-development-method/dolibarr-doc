# Customer invoice line commands

The invoice owns the commercial line through `facturedet.fk_facture`. The line's `rowid` identifies the mutation target. A product reference, parent line, prior progress line, supplier price and fixed discount identify five different relationships. A repeated product can legitimately create several lines on one invoice.

## Writable input matrix

The nested create operation reads **28 named body fields**. The nested amendment reads **23**. The following rows enumerate their union. Fields absent from a particular mapping have no direct effect through that command.

| Name in the request | Add to an existing draft | Amend an existing draft line |
| --- | --- | --- |
| `desc`, `label`, `ref_ext` | Filter the description as restricted rich text, sanitize the legacy label and store the external reference. The description is trimmed. | Replace the wording and reference. An empty external reference clears it. |
| `subprice`, `price_base_type` | Default basis is `HT` (exclusive of main VAT). `TTC` means inclusive of main VAT, before local taxes. The service forwards the submitted unit value in both potential input slots and the basis selects one. The stored `subprice` is the resulting net unit price before discount. | Accept one unit amount with the selected basis. Resending a previously stored net unit as `TTC` would extract VAT a second time. |
| `qty`, `remise_percent` | Numeric inputs, empty values normalize to zero before packaging. Discount is a percentage of the selling amount. | Replace and recalculate. The writer does not overlay just the field a caller happened to change. |
| `tva_tx`, `info_bits` | Supply a numeric rate or a rate with a parenthesized dictionary code. The numeric rate and `vat_src_code` are stored separately. An asterisk sets bit 1 for non-collected tax. | Same decomposition. Supplying only the bare rate clears the old code. |
| `localtax1_tx`, `localtax2_tx` | Inputs select local-tax treatment. Resolve the tax types and rates against the VAT treatment and parties. Store the resolved rate when that local amount is nonzero, otherwise zero. | Calculate the components again and write the passed, normalized rates with the resolved types. |
| `fk_product`, `product_type` | Positive product ID must exist. Its catalogue type takes precedence for calculation and persistence. Free lines use the submitted type. A negative type is rejected. | The product ID stays on the original line. The supplied type drives calculation and is written. Resend it explicitly for a service. |
| `date_start`, `date_end`, `fk_unit` | Optional service dates and unit of measure. Two nonempty dates with start later than end fail. | Replace dates and unit. Omission can clear an existing value. |
| `fk_parent_line`, `rang` | A type-9 structure row starts with no parent. Empty or negative parents normalize to zero. Missing, zero or minus-one rank appends after the invoice's highest rank for a top-level row. Under a parent it follows the highest sibling rank, falling back to the parent's rank for its first child. At an occupied positive rank the ordinary insert shifts subsequent ranks. A child triggers reordering. | Absent or zero rank leaves the stored rank unchanged in the row update. Moving between two different nonempty parents puts the line after the last rank of the new parent. A nonempty parent triggers reordering. |
| `fk_fournprice`, `pa_ht` | Supplier-price ID and buying cost feed margin calculation. With a price ID and empty cost, the initial lookup uses supplier unit price × (1 − supplier discount / 100). A genuinely missing cost can invoke the configured buying-cost fallback in the line writer. These are stored as `fk_product_fournisseur_price` and `buy_price_ht`. | Accepts the two inputs directly. Missing cost and an explicit zero cost can follow different branches. These amounts do not replace the selling unit price. |
| `fk_code_ventilation`, `fk_remise_except` | Accounting account assignment ID, normally zero until preparation, and optional absolute-discount ID. A missing or already line-consumed discount aborts the ordinary insertion. | Neither is mapped by the nested amendment. Account assignment has its own operation. |
| `origin`, `origin_id` | Passed to the line object during creation. They are not two persisted origin columns of the base detail table. | Neither is mapped. Use the document relationship for a durable link between commercial documents. |
| `situation_percent`, `fk_prev_id` | Progress used in pricing and predecessor detail ID. A missing, blank or above-100 percentage defaults to zero for an incremental progress invoice and to 100 otherwise. | Only the percentage is writable. When the non-final-cycle check runs, the proposed progress must be strictly below the percentage of the fetched nondraft successor if one exists. No matching successor passes that check. |
| `special_code`, `array_options` | Special handling code and per-line configurable field values. | Empty or 3 normalizes to zero for the special code. Only supplied configurable field entries replace the previously loaded entries. |
| `multicurrency_subprice` | This command passes zero as the foreign input and derives it from the base unit and header exchange rate. | This command accepts the foreign unit. When the base unit is zero and the foreign amount and rate are nonzero, base unit = foreign unit / rate. At a nonunit rate the two currency totals are priced from their respective units. |

Caller-supplied totals do not replace the price calculation. For a normal credit note the quantity is stored as its absolute value and the net unit and company/foreign net, VAT and gross amounts are forced negative. Preserving an originating discount line's price sign requires *both* the negative-lines and keep-origin-discount-lines options. Creation also applies the sign normalization to local-tax totals. Amendment writes the calculated local-tax totals directly.

## Writes, readback and failure

| Operation | Required state and result |
| --- | --- |
| Read lines | Invoice-read grant, existing parent and access to that invoice. Returns its cleaned lines. |
| Add | Requires invoice-create grant, existing accessible parent and draft status. Insert the row, save configurable values, consume the optional absolute discount, emit `LINEBILL_INSERT`, refresh header totals and reorder as needed. Successful result is the new detail ID. Rejected insert, including a nondraft parent, maps to 400. A checked failure rolls back the surrounding insert transaction. |
| Amend | Check invoice-create grant, accessible parent, existence of detail and matching `fk_facture`. Missing records return 404 and mismatched ownership returns 403. Load previous values, write the line and configurable values, emit `LINEBILL_MODIFY`, reorder a child and call header repricing. The outer method does not test the repricing return before committing the successful line write. A nonpositive mutation result maps to 304, including a rejected nondraft amendment. |
| Remove | Requires invoice-create grant, an accessible draft and a nonempty detail ID. Nondraft returns 403. Verify the loaded line belongs to that invoice. Emit `LINEBILL_DELETE`, delete configurable values, clear any matching `societe_remise_except.fk_facture_line` and clear both invoice links on matching `element_time` records. Delete the detail and check header repricing before commit. A failed domain removal maps to 405. |

Amendment and removal finish with a fresh invoice read requiring the separate read grant. A readback failure can follow a durable write. A fresh line insertion has no request-level deduplication key. After an interrupted response, reconcile the draft details and resulting totals before attempting another insertion. Emitted line events precede final header repricing.

## Ordering changes the accepted quantity

For a positive pack size, packaging rounds the magnitude up to a multiple and restores the sign. A magnitude below one pack becomes one full pack, including a zero request if it reaches this rule. Addition checks sufficient stock against the requested quantity **before** packaging. Amendment rounds using the existing line's packaging **before** testing available stock. A stock-managed item with real stock 5, a pack of 4 and a request for 5 illustrates the difference. Addition passes the stock comparison and computes prices on 8. With the same current stock and both policies enabled, amendment of the existing catalogue line to 5 checks 8 against 5 and fails. Neither operation in this example is the later validation movement.

For an ordinary unrounded pack of one, pricing three units at 12.50 net with a 20% line discount and 15% VAT yields 30.00 net, 4.50 VAT and 34.50 gross. Changing to four units while resending those financial inputs yields 40.00 net, 6.00 VAT and 46.00 gross. A supplier cost of 7.00 per unit changes the margin to 12.00 on the amended four units. The customer's gross remains 46.00.
