# Draft creation and source conversion

The invoice header, its customer and its lines have separate identities. Where a billing process originates from an order or contract, the commercial document link preserves that origin even after a draft line is edited.

## Direct creation with lines

1. Require invoice-create permission. The only named mandatory header input in this service is `socid`. Missing customer ID returns 400. An unknown customer or a customer outside the caller's visibility returns 404. Supplying `id` returns 400. An explicit `entity` must equal the caller's entity, otherwise the request returns 403.
2. Apply recognized input conversions. A `caller` value becomes synchronization context for event handlers. An absent `date` defaults to the current time. An explicitly empty date reaches the domain requirement for a nonempty invoice date. A nonempty `date_lim_reglement` overrides calculation from payment terms.
3. Save a draft header and give it a provisional reference derived from its new row ID. A supplied currency code and nonzero rate preserve that rate if the currency is recognized. A recognized code without a rate invokes the exchange-rate lookup. Without a resolved currency ID the header uses company currency and rate one.
4. For a batch of line maps, process a copy in input order, assigning the newly created invoice ID to each detail. Treat `subprice` as **net**. This path fixes the basis to `HT`. It forwards `multicurrency_subprice` when supplied, and attaches `vat_src_code` to `tva_tx` if the rate has no parenthesized code. It computes amounts from quantities, prices, rates, discounts and progress. Supplied total fields do not override the result.
5. Build the structural hierarchy while inserting. A type-9 row clears the current parent for its own insert and becomes the new parent after it receives a line ID. An ordinary row with a nonempty `fk_parent_line` uses that current new parent. An ordinary row with an empty parent resets the cursor to zero. A source parent ID serves as a flag on this path. It is not copied literally into the new hierarchy.
6. Defer header repricing until all details succeed. After repricing, save the header's configurable values, emit `BILL_CREATE` and commit. Line events can observe the detail before the final header amount. A checked line failure, unsuccessful final repricing or veto of the header event rolls back this creation. Successful response is the new invoice ID.

For example, submit in order a section, two children flagged with an old section ID, and an independent service with no parent. If the new section gets ID 501, both child rows point to 501 and the service has no parent. Reordering the service between the section and the second child resets the current parent before that child. Loading the old section by its supplied numeric ID would produce a different and incorrect hierarchy.

A line amount of 115.00 inclusive of 15% main VAT can be supplied on the [standalone line command](line-commands.md) as `subprice = 115` with `price_base_type = TTC`. In a header batch enter `subprice = 100` to produce the same net 100.00, VAT 15.00, gross 115.00. Entering 115 in the batch would produce gross 132.25.

## Order and contract conversion

| Decision | Order | Contract |
| --- | --- | --- |
| Who can start? | Requires order-read and invoice-create grants and access to the source order. Zero source ID returns 400. An order whose status is at or below draft, or whose billed flag is already set, returns 405. | Requires contract-read and invoice-create grants and access to the contract. Zero source ID returns 400. This service does not apply the order status or billed-flag test. |
| Which lines? | The conversion iterates the loaded order detail list. The service accepts an order ID and has no selection of individual rows or remaining delivery quantities. | The business operation can take a list of contract-line IDs. Its service invokes the default all-lines form. A service that requires a partial recurring bill must select that operation explicitly. |
| Which header values? | Set invoice date to now. Carry customer, project, bank, payment method and terms, availability, demand reason, requested delivery date, named contact, customer reference, trade terms and their location. Copy public/private notes unless propagation is disabled. | Carry customer, project, bank, terms and payment method, availability, demand reason, requested delivery date, named contact and customer reference. The contract mapper shown here assigns no trade-term fields. Notes follow the same propagation option. |
| Which values on each line? | Copy description, label, net unit, discounts, quantity, product/type, tax code and rates, local taxes, service interval, hierarchy, rank, unit, margin inputs and configurable values. | Uses the corresponding source fields for each selected contract detail, including margin inputs and configurable values. |
| Which identities survive? | The new invoice and each detail receive new IDs. Register the origin document and include other supplied linked objects. Transfer header configurable fields. | Register the contract as the origin, include supplied linked objects, and transfer header configurable fields. |
| When is the result durable? | The core draft creation completes before the post-conversion extension point. A failure at that later point can be returned as 405 after the new draft was created. | The same post-creation extension boundary applies. Inspect linked invoices before retrying that outcome. |

The two converters copy currency values onto the intermediate detail objects, including the foreign unit and line totals. Neither mapper assigns the source currency code and rate to the **invoice header** in the ordinary mapping. The core draft creator resolves the destination currency from its own header, and recalculates details. To reconcile a converted foreign order, check the actual destination header code and rate and its persisted company and foreign totals. Copying input line totals into intermediate objects does not establish that the resulting invoice uses the source document currency.

For a validated unbilled order containing two billable services, conversion creates a draft with both. A commercial payment, sales journal transfer and an order-classification action are independent of this result. The conversion has no request deduplication key. Until the order is classified as billed, the service's eligibility check alone cannot prove that another draft was never created.
