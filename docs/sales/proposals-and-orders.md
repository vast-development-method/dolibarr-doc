# Commercial proposals and customer orders

A proposal records an offer on agreed terms. The customer order records the commitment to fulfil it. Conversion creates another document with its own ID, lines, dates and number. Both remain available for audit. A sale can also begin with an order or proceed from a signed proposal to an invoice. | Order header | Entity, reference, party, optional project, order and delivery dates, delivery address and warehouse, payment terms, optional deposit, currency, total net/tax/gross, fulfilment status and separate billed flag. |
| Commercial line | Belongs to one stage-specific header. Catalogue reference is optional. ## State transitions

| Document | Normal path and alternatives | Effects |
| --- | --- | --- |
| Proposal | Draft (0) → validated (1) → signed (2) or refused (3). Signed → billed (4). Cancelled is −1. | Validation takes a provisional reference through the numbering rule, records validator/date and emits `PROPAL_VALIDATE`. A decision appends the supplied notes. Signing records signature details, promotes the party to customer and emits `PROPAL_CLOSE_SIGNED`. Refusal emits `PROPAL_CLOSE_REFUSED`. |
| Reopened proposal | In the card flow, signed, refused, billed and cancelled documents can return to validated, subject to permissions and available actions. With `PROPAL_SKIP_ACCEPT_REFUSE` the card can decide a draft and can reopen to draft. | Reopening updates the existing proposal. Creating a later order is a different operation. |
| Order | Draft (0) → validated (1) → shipment in process (2) → closed/delivered (3). Closing can also take a validated order directly to delivered. Cancelled is −1. | Validation promotes the party, numbers the order, records validator/date and can issue stock. Closing records closer/date and emits `ORDER_CLOSE`. Billing is independently classified on a post-draft order. |

## Pricing a line

For an ordinary taxable product with tax-exclusive input, one VAT rate, full progress and no local taxes, the net is quantity × unit price × (1 − discount / 100). VAT is net × VAT rate / 100. Gross is net + VAT. Example: 10 units at 50, discount 10%, VAT 15% gives 450 net, 67.50 VAT and 517.50 gross. The stored unit price remains 50. This example uses exact amounts at two decimal places. [Line calculation and persistence](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/commande/class/commande.class.php#L1749-L1849) · [Pricing engine](https://github.com/Dolibarr/dolibarr/blob/5c6c7ff6a5112413b1c27221c8d11750afad56f8/htdocs/core/lib/price.lib.php#L90-L379)

The engine distinguishes tax-exclusive and tax-inclusive price input, local tax types, progress and document currency. Use each line's tax basis and then aggregate stored totals. A single rate applied to the header total cannot reconstruct mixed-rate sales. When customer packaging is enabled the order line quantity may be adjusted to packaging before pricing. Date-bounded services reject an end before the start. A zero-quantity ordinary line receives the option marker. ## Conversion contract

1. Start with an accessible proposal. The card enables **Create order** for signed proposals with the order module enabled. The REST conversion requires proposal read, order create and access to that proposal. Its handler delegates to conversion without its own signed-state check. An integration implementing the ordinary acceptance workflow must check the source state.
2. Create a new order dated now. Copy the party, project, payment terms, deposit, shipping details and customer reference. Copy line quantities, descriptions, units, price, discount and tax inputs. Recompute the margin basis and new totals. Notes propagate unless disabled. Only header extra fields supported on the destination are selected.
3. If multicurrency is enabled, carry the currency. Reuse the proposal rate when the origin-rate option is enabled and a rate is present. Otherwise the lookup uses the order date. A failed currency-ID resolution falls back to company currency at rate 1.
4. Save the draft order with its source document link and run the creation hooks. Validation is a subsequent command. With the Workflow module and `WORKFLOW_PROPAL_AUTOCREATE_ORDER`, signing can perform order creation. That workflow first checks for an already linked order. The explicit REST conversion does not implement the same duplicate check. After an uncertain response, read the proposal's linked orders before creating another.

## Service contracts and acceptance cases

| Service or case | Preconditions and input | Observable result |
| --- | --- | --- |
| Create proposal/order | Module create right, accessible party, request fields for that resource | Returns the new ID. A missing or inaccessible party gives 404. The public REST create and convert methods have different return shapes. |
| Validate an order | Order create and resource access in REST. Advanced permissions enable a distinct order-validation right in the business operation. Use a warehouse appropriate to the configured stock event. | Returns refreshed order. Retrying while already validated yields 304. A failed stock movement or negative validation trigger rolls back database changes in this validation. |
| SALES-1 | Sign a validated prospect proposal, with the workflow and automatic order creation enabled. | Party receives the customer role. A linked draft order appears. The workflow's existing-link guard suppresses a second automatic order for that proposal. |
| SALES-2 | Change a catalogue selling price after issuing the quote and convert the quote. | The newly constructed line uses the proposal's unit price and discount. The pricing trace uses those document inputs. |
| SALES-3 | Record 10 × 50 as in the example and mark the delivered order billed. | Sales amounts remain 450 / 67.50 / 517.50. Status remains delivered with billed=true. No payment amount is implied. |
| SALES-4 | Try to validate a draft containing a catalogue item disabled for sale with the default active-product check enabled. | Validation rejects it before numbering or stock issue. Each of the two sales documents has its own option to disable this check. |
