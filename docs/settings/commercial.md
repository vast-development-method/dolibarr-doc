# Sales, shipment and purchasing settings

These 16 settings are available on five commercial setup screens in release 24.0.3. Each entry identifies where the operator makes the choice and where the running system uses it. A module activation default is identified explicitly where the release declares one.

## Customer proposals and orders

A proposal can expire, be signed and be downloaded. These are three distinct operations. Its validity period is saved with the proposal. Its signature and download controls govern what the system offers when communicating about the document. See [proposals and orders](../sales/proposals-and-orders.md).

| Operator choice | Effect | Setup and consuming operation |
| --- | --- | --- |
| Default validity in days · `PROPALE_VALIDITY_DURATION` | The module supplies **15 days** on activation. The proposal form starts with this number and allows the author to replace it. Creation calculates the end of validity from the proposal date and the duration entered for that proposal. | `htdocs/admin/propal.php:653`, `htdocs/core/modules/modPropale.class.php:96`, `htdocs/comm/propal/card.php:2550`, `htdocs/comm/propal/class/propal.class.php:1188` |
| Offer online signature · `PROPOSAL_ALLOW_ONLINESIGN` | The module enables this on activation. With the option on, a proposal that has left draft can display its signature link. The signer still has to complete the signature operation. Turning the option off suppresses that card link. | `htdocs/admin/propal.php:697`, `htdocs/core/modules/modPropale.class.php:110`, `htdocs/comm/propal/card.php:3873` |
| Include a proposal download link · `PROPOSAL_ALLOW_EXTERNAL_DOWNLOAD` | When on, generating a message for an existing customer proposal can fill the proposal-download template field with the last main document's link. When off, that field is empty. Generating a new copy of the proposal and sending the message are separate actions. | `htdocs/admin/propal.php:690`, `htdocs/core/lib/functions.lib.php:10789`, `htdocs/core/class/commonobject.class.php:1228` |
| Include a customer-order download link · `ORDER_ALLOW_EXTERNAL_DOWNLOAD` | This independent switch controls the corresponding template field for an existing customer order. An order message can offer the last main order document when the setting is on and a shareable document is available. | `htdocs/admin/order.php:704`, `htdocs/core/lib/functions.lib.php:10794`, `htdocs/core/class/commonobject.class.php:1228` |
| Suppress manual billing classification on the order card · `ORDER_DISABLE_CLASSIFY_BILLED_FROM_ORDER` | This control is shown when invoicing is active. Enabling it hides both manual billing switches on the customer-order card. With it off, an authorised order editor can change classification on an eligible validated order when billing on shipment is inactive. Marking an unbilled order also requires a nonnegative tax-inclusive total. | `htdocs/admin/order.php:713`, `htdocs/commande/card.php:3671`, `htdocs/commande/card.php:3676` |

An author using the 15-day default can enter 30 on a particular proposal. Its validity end is calculated from that proposal's 30-day duration. Sending the resulting file and asking the recipient to sign it remain separate choices.

## Shipment preparation

The picking form resolves source order lines, remaining quantities and eligible warehouse or lot positions. These controls affect data entry, the ordering of suggestions, and how a recipient can acknowledge a shipment. See [dispatch through invoicing](../sales/dispatch-to-invoice.md).

| Operator choice | Effect | Setup and consuming operation |
| --- | --- | --- |
| Leave shipment quantities blank · `SHIPMENT_DONT_PREFILL_QTY` | The shipment form defaults this switch to false if unset. With it off, eligible quantity inputs start with the calculated deliverable quantity. With it on, the field starts empty so the operator enters the quantity actually picked. The form can still show the supporting warehouse and lot information. | `htdocs/admin/expedition.php:506`, `htdocs/expedition/card.php:2144`, `htdocs/expedition/card.php:2290` |
| Show entry date for candidate lots · `SHIPPING_DISPLAY_STOCK_ENTRY_DATE` | Turning this on adds the entry-date column to shipment preparation. For each candidate warehouse lot, the lookup derives the latest matching incoming movement date by lot identifier and warehouse. It sorts candidates by that date ascending, then by lot identifier, before the remaining criteria. A replenished lot can therefore show a date later than its original arrival. | `htdocs/admin/expedition.php:457`, `htdocs/expedition/card.php:1957`, `htdocs/product/class/productbatch.class.php:499`, `htdocs/product/class/productbatch.class.php:512`, `htdocs/product/class/productbatch.class.php:528` |
| Offer shipment signature · `EXPEDITION_ALLOW_ONLINESIGN` | When on, the shipment card can show the recipient's signature link once the shipment has left draft. Turning it off suppresses the link. This setting belongs to shipment acknowledgement independently of the signature option on sales proposals. | `htdocs/admin/expedition.php:498`, `htdocs/expedition/card.php:3918` |

## Supplier orders

These decisions occur at three different points in a purchase's life. The order is authorised for placement, its deliveries are reviewed, and its billing status is reconciled. A delivery review can hold up completion of receiving even after the physical dispatch lines have been recorded. See [supplier ordering](../supply/purchasing.md) and [supplier bills and allocations](../supply/payables.md).

| Operator choice | Effect | Setup and consuming operation |
| --- | --- | --- |
| Require two approvals at or above a threshold · `SUPPLIER_ORDER_3_STEPS_TO_BE_APPROVED` | Supply a positive amount to apply a second approval level when the order's tax-exclusive total reaches that amount. Blank or zero leaves the threshold inactive. The workflow records each level's approver and date. The order remains validated while an applicable approval is outstanding, then becomes approved. The second-level action has its own permission. | `htdocs/supplier_order/admin/supplier_order.php:177`, `htdocs/supplier_order/admin/supplier_order.php:501`, `htdocs/fourn/commande/card.php:2934`, `htdocs/fourn/class/fournisseur.commande.class.php:1333` |
| Review order-based receipt lines · `SUPPLIER_ORDER_USE_DISPATCH_STATUS` | The setup offers this switch when the separate reception module is inactive. With it on, the purchase-order dispatch screen presents a status for each recorded delivery line and supports review actions. Attempting to mark receiving complete fails while lines still await review. | `htdocs/supplier_order/admin/supplier_order.php:532`, `htdocs/fourn/commande/dispatch.php:1275`, `htdocs/fourn/commande/dispatch.php:1395`, `htdocs/fourn/class/fournisseur.commande.class.php:2748` |
| Require a linked supplier bill for manual billing classification · `SUPPLIER_ORDER_DISABLE_CLASSIFY_BILLED_FROM_SUPPLIER_ORDER` | With invoicing active, switching this on makes the purchase-order card require at least one linked supplier bill before it offers the action to mark the order billed. With the switch off, the card can offer the action without a linked bill. Order state, the current billing flag and the user's rights still apply. The card has a separate branch when invoicing is inactive. | `htdocs/supplier_order/admin/supplier_order.php:550`, `htdocs/fourn/commande/card.php:3051` |
| Include a supplier-order download link · `SUPPLIER_ORDER_ALLOW_EXTERNAL_DOWNLOAD` | With the switch on, a message concerning an existing purchase order can include a direct link to its last main document. With it off, the supplier-order download template field is empty. | `htdocs/supplier_order/admin/supplier_order.php:557`, `htdocs/core/lib/functions.lib.php:10819`, `htdocs/core/class/commonobject.class.php:1228` |

For a threshold of 5,000, a tax-exclusive order of 4,999.99 stays on single approval. At exactly 5,000 the threshold applies. After the first approval alone the order stays validated. Once both required approvals have been recorded it can move to approved.

## Supplier price requests

A request can have a provisional identifier while its prices and terms are being assembled. The numbering and document models have distinct roles when the buyer validates the request and generates its outward-facing document. See the [purchasing workflow](../supply/purchasing.md).

| Operator choice | Effect | Setup and consuming operation |
| --- | --- | --- |
| Numbering model · `SUPPLIER_PROPOSAL_ADDON` | Choose the active numbering model for supplier price requests. The supplied module default is `mod_supplier_proposal_marbre`. On validation, a request whose reference is provisional or empty obtains its next number from the selected model. A request already carrying a final reference retains it. | `htdocs/supplier_proposal/admin/supplier_proposal.php:200`, `htdocs/supplier_proposal/admin/supplier_proposal.php:314`, `htdocs/core/modules/modSupplierProposal.class.php:90`, `htdocs/supplier_proposal/class/supplier_proposal.class.php:1586`, `htdocs/supplier_proposal/class/supplier_proposal.class.php:2553` |
| Default document model · `SUPPLIER_PROPOSAL_ADDON_PDF` | The supplied activation default is `aurore`. Generation gives precedence to an explicitly requested model, then the model on the request and finally the configured default. This choice determines how the outward-facing request is rendered. | `htdocs/supplier_proposal/admin/supplier_proposal.php:189`, `htdocs/supplier_proposal/admin/supplier_proposal.php:456`, `htdocs/core/modules/modSupplierProposal.class.php:83`, `htdocs/supplier_proposal/class/supplier_proposal.class.php:2844` |
| Draft watermark · `SUPPLIER_PROPOSAL_DRAFT_WATERMARK` | Enter the text that the supplied default PDF model stamps on a draft. An empty value produces no configured watermark. The model applies this text only while rendering a draft request. | `htdocs/supplier_proposal/admin/supplier_proposal.php:554`, `htdocs/core/modules/supplier_proposal/doc/pdf_aurore.modules.php:190` |
| Standard footer text · `SUPPLIER_PROPOSAL_FREE_TEXT` | Enter wording to accompany supplier price requests, such as purchasing terms. The supplied PDF models pass the setting to their page-footer renderer. The template, generation options and the document being produced determine its presentation. | `htdocs/supplier_proposal/admin/supplier_proposal.php:534`, `htdocs/core/modules/supplier_proposal/doc/pdf_aurore.modules.php:1443`, `htdocs/core/modules/supplier_proposal/doc/pdf_zenith.modules.php:1509` |
