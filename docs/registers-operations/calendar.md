# Calendar activities

One activity in `actioncomm` requires a matching `c_actioncomm` type. Its party and additional fields are optional. Choosing a resource adds an inner join on `element_resources` for the action's ID and element type `action`, with an exact resource ID. The activity must belong to an allowed agenda entity. The register checks personal-agenda read permission. On ordinary navigation users without all-agenda read access, and users choosing “mine”, are scoped to their own calendar. External party context sets the party selection. Where customer visibility is restricted by sales assignment, activities without a party or with the viewer as that party's representative qualify.

| Input | Predicate |
| --- | --- |
| `search_filtert` / `filtert`, `search_usergroup` / `usergroup` | A selected user matches the activity owner, or a user assignment on an activity owned by someone else. For a comma list the owner test uses the first numeric ID, while the assignment branch uses the list. Hierarchy selection (−3) tests user assignments for the hierarchy. Group selection tests assigned users' group membership when the individual/hierarchy branch has not been chosen. With no owner choice the view can default to the viewer under the calendar setting. |
| `search_resourceid`, `search_projectid`, `search_socid`, `search_type` | Exact resource, project, party or type-dictionary ID. The unprefixed equivalents are accepted. |
| `search_actioncode` | Manual and automatic groups compare the type classification with `systemauto`. With event types enabled, other selected codes match `c_actioncomm.code` by inclusion. With types disabled the special “other” manual/automatic values stand for those two groups. A configured default can supply a missing action type. |
| `search_status` / `status` | `0` means percentage zero, `na` means −1, `50` means strictly between zero and 100, `done` or `100` means exactly 100, `todo` means at least zero and below 100. An omitted selector may take the configured default. |
| `search_id`, `search_title`, `search_note`, `search_import_key`, `search_categ_cus` | Numeric activity ID, keyword searches on label/note/import key, and any selected activity-category ID. Category −2 requires no category link. |
| `dateselect` day/month/year | With an end present, require end at or after the start of the selected day and start no later than its last second. With no end, assume one hour: the start must be strictly later than one hour before the day and no later than its last second. |
| `datestart_dtstart/dtend`, `dateend_dtstart/dtend` | Independent inclusive day bounds on `datep` or `datep2`, in the user's time context. An explicit end-date range excludes rows lacking an end. Navigation year, month, day and birthday display controls are separate from these query predicates. |

Suppose one meeting starts 20 minutes before midnight with no saved end. It appears on the new day's overlap selection. Another begins exactly one hour before midnight with no end and is excluded by the strict lower bound. A third meeting with a saved end exactly at midnight is included. A 20-percent-complete meeting appears in both **started** and **to do**. These views overlap by design.
